Oui, on peut reproduire une grande partie du profil navigateur, et surtout conserver un vrai profil Chromium au lieu de ne transférer que les cookies.

La nuance importante est la suivante : il faut conserver le navigateur et son contexte, pas simplement copier cf_clearance vers impit.

Ce que le profil persistant peut conserver
cf_clearance et les autres cookies ;
localStorage, sessionStorage, IndexedDB ;
cache HTTP et service workers ;
état JavaScript du challenge ;
User-Agent et Client Hints ;
viewport, écran, langue, timezone ;
permissions, fonts, WebGL, canvas et caractéristiques Chromium ;
même proxy et même IP Decodo ;
continuité du profil entre les scans.
Ce que fait actuellement le projet
Le flux actuel :

démarre Playwright ;
résout Cloudflare ;
extrait allCookies ;
ferme le navigateur ;
effectue les scans suivants avec impit.
Donc seul l’état cookie est conservé. Le profil Chromium complet est perdu lorsque le navigateur est fermé. C’est la raison pour laquelle cette architecture est moins fidèle qu’un vrai navigateur persistant.

Architecture correcte
Je recommande :

Un processus Chromium persistant
        │
        ├── profil CF principal
        │     ├── cookies
        │     ├── localStorage
        │     ├── cache
        │     └── état JavaScript
        │
        ├── contexte dossier A
        │     └── PHPSESSID_A
        │
        ├── contexte dossier B
        │     └── PHPSESSID_B
        │
        └── même proxy Decodo / même IP

Le profil CF serait résolu une seule fois et conservé sur disque. Pour chaque dossier, on créerait ensuite un contexte isolé avec :

le même état CF ;
le même proxy ;
un PHPSESSID propre ;
un stockage applicatif séparé.
Ainsi, on conserve la continuité Cloudflare tout en évitant le conflit Bookitit entre les dossiers.

Limite de l’approche HTTP-only
Même avec tous les cookies copiés, impit ne reproduira pas exactement :

l’exécution JavaScript ;
le fingerprint TLS/HTTP2 exact de Chromium ;
WebGL/canvas ;
les service workers ;
les signaux comportementaux ;
le cache interne Chromium.
Pour reproduire réellement l’intégralité du profil, il faut donc garder les scans dans Chromium persistant. Le coût sera plus élevé en RAM et probablement en trafic, mais le comportement sera beaucoup plus proche du navigateur réel.

Le bon compromis serait de conserver deux modes :

SPAIN_SESSION_MODE=persistent-browser

pour le mode fidèle avec Chromium persistant, et le mode HTTP actuel comme fallback économique.
