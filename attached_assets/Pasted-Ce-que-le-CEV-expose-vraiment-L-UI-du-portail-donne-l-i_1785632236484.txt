Ce que le CEV expose vraiment
L'UI du portail donne l'impression d'un flow en 3 étapes :

Choisir une date → 2. Voir les heures → 3. Voir les places par heure
Mais techniquement, le HTML de /Integration/VOW/SelectSlot embed en une seule fois toute la table de disponibilités dans la page, sous forme d'un tableau JSON inlinisé :

availability = [
  { datePart: "2026-12-22T00:00:00", timeSlot: "2026-12-22T14:20:00", scheduleLineId: "uuid-A" },
  { datePart: "2026-12-22T00:00:00", timeSlot: "2026-12-22T14:20:00", scheduleLineId: "uuid-B" },
  { datePart: "2026-12-23T00:00:00", timeSlot: "2026-12-23T14:20:00", scheduleLineId: "uuid-C" },
  ...136 entrées...
]

Chaque entrée = 1 place (scheduleLineId = clé de réservation). Même date/heure = plusieurs places disponibles pour ce créneau.Notre stratégie actuelle
Étape	Ce qu'on fait
1. Setup	1 seul GET + résolution captcha → on récupère le HTML complet avec les 136 places
2. Extraction	On parse le tableau availability[] en entier → on groupe par (date, heure) → on calcule free = nb de places par créneau
3. Sélection	On trie par free décroissant, on préfère free ≥ 3 → le slot avec le plus de places = moins de concurrence
4. Booking	On soumet directement via HTTP (POST /SelectSlot avec scheduleLineId) → confirmation en <1 seconde
Group booking : si 3 personnes d'une même famille ont besoin d'un RDV le même jour à la même heure → le bot ne cherche pas ça. Il book le meilleur créneau disponible pour chaque dossier indépendamment, sans coordination inter-dossiers. Partage de session cross-dossiers : chaque dossier a sa propre session.
