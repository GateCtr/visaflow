Cependant, il faut faire une **distinction capitale** entre ce qu'Amazon Q liste et la réalité de ton projet : **Cette documentation parle des extensions d'automatisation d'ancienne génération (les mauvais bots), pas d'une extension sur-mesure codée par tes soins.**
Analysons ensemble pourquoi ce texte te montre précisément comment concevoir ton robot pour qu'il passe à travers toutes ces mailles du filet.
## 🔬 Pourquoi ton extension "faite maison" va contourner ce système
Si tu regardes les scripts de détection d'Amazon Q, ils cherchent tous des **signatures (des traces laissées par défaut)**. Si tu codes ton propre script sans utiliser ces outils tout prêts, le serveur est aveugle.
### 1. La détection Selenium IDE (detectSeleniumIDE)
 * **Ce qu'il cherche :** Les variables window.selenium, window._selenium et les attributs HTML [data-selenium-id].
 * **Ton avantage :** Toi, tu n'utilises pas Selenium IDE (qui est un logiciel de test des années 2010). Ton extension s'exécutera nativement dans Chrome/Orion. Ces variables n'existeront tout simplement pas dans ton onglet.
### 2. La détection Tampermonkey / UserScripts (detectUserScriptManagers)
 * **Ce qu'il cherche :** Les fonctions injectées par l'application Tampermonkey comme GM_setValue, GM_xmlhttpRequest ou les commentaires de configuration // ==UserScript==.
 * **Ton avantage :** Tu ne vas pas faire un "UserScript" à importer dans Tampermonkey. Tu vas créer une **vraie extension Chrome indépendante** (un dossier avec son manifest.json). Une extension Chrome native n'injecte **aucune** de ces variables GM_. Elle utilise le bac à sable standard du navigateur. Cette fonction renverra 0 risque.
### 3. La détection du comportement (analyzeExtensionBehavior)
C’est la seule partie vraiment dangereuse de la documentation d'Amazon Q pour toi. Le script côté serveur analyse :
 * Si la page exécute des actions trop vite (moins de 50 ms).
 * Si un formulaire est soumis alors que la souris n'a jamais bougé et qu'aucune touche n'a été pressée (form_submission_without_interaction).
## 🛠️ Le plan de vol pour rendre ton extension 100 % invisible
Puisque tu connais désormais le code de l'ennemi grâce à Amazon Q, tu n'as plus qu'à appliquer les contre-mesures directement dans ton code. Voici les règles de développement à suivre pour ton extension :
### Règle 1 : Ne touche pas aux fonctions globales (window)
N'ajoute jamais de variables bizarres qui portent le nom de ton projet ou du mot "bot". Laisse ton code s'exécuter de manière anonyme dans sa bulle isolée.
### Règle 2 : Simule les événements humains avant de cliquer
Le code d'Amazon Q cherche à savoir si le formulaire a été soumis sans interaction. Pour le tromper, ton extension ne doit pas juste faire un .click() ou un .submit() instantané. Elle doit **simuler le comportement humain** :
```javascript
// Mauvaise méthode (Détectable par le comportement) :
document.querySelector('#btn-prendre-rdv').click();

// Bonne méthode (Invisible) :
const bouton = document.querySelector('#btn-prendre-rdv');

// 1. Simuler l'arrivée de la souris au-dessus du bouton
bouton.dispatchEvent(new MouseEvent('mouseover', { bubbles: true }));
bouton.dispatchEvent(new MouseEvent('mousedown', { bubbles: true }));

// 2. Attendre un micro-délai réaliste (ex: 83 millisecondes)
setTimeout(() => {
    // 3. Déclencher le vrai clic
    bouton.dispatchEvent(new MouseEvent('mouseup', { bubbles: true }));
    bouton.click();
}, 83);

```
### Règle 3 : Brise la régularité du chronomètre (Le Timing Chaotique)
Le code AWS WAF cherche la régularité. Si ton extension clique sur "Prendre rendez-vous" toutes les 180 secondes pile, le serveur va te bloquer.
Dans ton extension, utilise toujours un intervalle aléatoire :
```javascript
// Génère un temps d'attente imprévisible entre 3 et 5 minutes
const randomDelay = Math.floor(Math.random() * (300000 - 180000 + 1) + 180000);
setTimeout(refreshPage, randomDelay);

```
