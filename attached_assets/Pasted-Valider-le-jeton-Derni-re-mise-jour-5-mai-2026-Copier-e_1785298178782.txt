Configuration de l'agent
Découvrez comment valider en toute sécurité les jetons Turnstile sur votre serveur à l'aide de l'API Siteverify.

Validation obligatoire côté serveur

Vous devez appeler l'API Siteverify pour terminer votre implémentation Turnstile. Le widget côté client à lui seul ne protège pas vos formulaires.

La validation côté serveur est requise car :

Les jetons peuvent être falsifiés. Un attaquant peut soumettre n’importe quelle chaîne au point de terminaison de votre formulaire sans relever de défi.
Les jetons expirent. Chaque jeton est valable 300 secondes (5 minutes) après la génération.
Les jetons sont à usage unique. Chaque jeton ne peut être validé qu'une seule fois. Un jeton rejoué sera rejeté avec le codetimeout-or-duplicate d'erreur.
Processus
Le client génère un jeton : le visiteur termine le défi Turnstile sur votre page Web.
Jeton envoyé au serveur : la soumission du formulaire inclut le jeton Turnstile.
Le serveur valide le jeton : votre serveur appelle l'API Siteverify de Cloudflare.
Cloudflare répond : Renvoiesuccess oufailure et des données supplémentaires.
Le serveur prend des mesures : autoriser ou rejeter la demande d’origine en fonction de la validation.
Présentation de l'API Siteverify
Point final
coquille
POST https://challenges.cloudflare.com/turnstile/v0/siteverify

Format de la demande
L'API accepte les requêtesapplication/x-www-form-urlencoded etapplication/json, mais renvoie toujours des réponses JSON.

Paramètres requis
Paramètre	Requis	Description
secret	Oui	La clé secrète de votre widget depuis le tableau de bord Cloudflare
response	Oui	Le jeton du widget côté client
remoteip	Non	L'adresse IP du visiteur
idempotency_key	Non	Un UUID que vous générez pour réessayer les demandes de validation en toute sécurité
Caractéristiques du jeton
Longueur maximale : 2048 caractères
Période de validité : 300 secondes (5 minutes) à partir de la génération
Utilisation unique : Chaque jeton ne peut être validé qu'une seule fois
Expiration automatique : les jetons expirent automatiquement et ne peuvent pas être réutilisés
Le jeton de validation émis par Turnstile est valable cinq minutes. Si un utilisateur soumet le formulaire après cette période, le jeton est considéré comme expiré. Dans ce scénario, l'API de vérification côté serveur renverra un échec et leerror-codes champ de la réponse incluratimeout-or-duplicate .

Pour garantir une validation réussie, le visiteur doit lancer la demande et soumettre le jeton à votre backend dans un délai de cinq minutes. Sinon, le widget Turnstile doit être actualisé pour générer un nouveau jeton. Cela peut être fait en utilisant laturnstile.reset fonction.

const SECRET_KEY = "your-secret-key";

async function validateTurnstile(token, remoteip) {
	try {
		const response = await fetch(
			"https://challenges.cloudflare.com/turnstile/v0/siteverify",
			{
				method: "POST",
				headers: {
					"Content-Type": "application/json",
				},
				body: JSON.stringify({
					secret: SECRET_KEY,
					response: token,
					remoteip: remoteip,
				}),
			},
		);

		const result = await response.json();
		return result;
	} catch (error) {
		console.error("Turnstile validation error:", error);
		return { success: false, "error-codes": ["internal-error"] };
	}
}

// Usage in form handler
async function handleFormSubmission(request) {
	const body = await request.formData();
	const token = body.get("cf-turnstile-response");
	const ip =
		request.headers.get("CF-Connecting-IP") ||
		request.headers.get("X-Forwarded-For") ||
		"unknown";

	const validation = await validateTurnstile(token, ip);

	if (validation.success) {
		// Token is valid - process the form
		console.log("Valid submission from:", validation.hostname);
		return processForm(body);
	} else {
		// Token is invalid - reject the submission
		console.log("Invalid token:", validation["error-codes"]);
		return new Response("Invalid verification", { status: 400 });
	}
}

Techniques avancées de validation
Clés d'idempotence pour l'opération de nouvelle tentative
js
const crypto = require("crypto");

async function validateWithRetry(token, remoteip, maxRetries = 3) {
	const idempotencyKey = crypto.randomUUID();

	for (let attempt = 1; attempt <= maxRetries; attempt++) {
		try {
			const formData = new FormData();
			formData.append("secret", SECRET_KEY);
			formData.append("response", token);
			formData.append("remoteip", remoteip);
			formData.append("idempotency_key", idempotencyKey);

			const response = await fetch(
				"https://challenges.cloudflare.com/turnstile/v0/siteverify",
				{
					method: "POST",
					body: formData,
				},
			);

			const result = await response.json();

			if (response.ok) {
				return result;
			}

			// If this is the last attempt, return the error
			if (attempt === maxRetries) {
				return result;
			}

			// Wait before retrying (exponential backoff)
			await new Promise((resolve) =>
				setTimeout(resolve, Math.pow(2, attempt) * 1000),
			);
		} catch (error) {
			if (attempt === maxRetries) {
				return { success: false, "error-codes": ["internal-error"] };
			}
		}
	}
}

Validation améliorée avec contrôles personnalisés
js
async function validateTurnstileEnhanced(
	token,
	remoteip,
	expectedAction = null,
	expectedHostname = null,
) {
	const validation = await validateTurnstile(token, remoteip);

	if (!validation.success) {
		return {
			valid: false,
			reason: "turnstile_failed",
			errors: validation["error-codes"],
		};
	}

	// Check if action matches expected value (if specified)
	if (expectedAction && validation.action !== expectedAction) {
		return {
			valid: false,
			reason: "action_mismatch",
			expected: expectedAction,
			received: validation.action,
		};
	}

	// Check if hostname matches expected value (if specified)
	if (expectedHostname && validation.hostname !== expectedHostname) {
		return {
			valid: false,
			reason: "hostname_mismatch",
			expected: expectedHostname,
			received: validation.hostname,
		};
	}

	// Check token age (warn if older than 4 minutes)
	const challengeTime = new Date(validation.challenge_ts);
	const now = new Date();
	const ageMinutes = (now - challengeTime) / (1000 * 60);

	if (ageMinutes > 4) {
		console.warn(`Token is ${ageMinutes.toFixed(1)} minutes old`);
	}

	return {
		valid: true,
		data: validation,
		tokenAge: ageMinutes,
	};
}

// Usage
const result = await validateTurnstileEnhanced(
	token,
	remoteip,
	"login", // expected action
	"example.com", // expected hostname
);

if (result.valid) {
	// Process the request
	console.log("Validation successful:", result.data);
} else {
	// Handle validation failure
	console.log("Validation failed:", result.reason);
}

Référence des codes d'erreur
Code d'erreur	Description	Action requise
missing-input-secret	Paramètre secret non fourni	Assurez-vous que la clé secrète est incluse
invalid-input-secret	La clé secrète n'est pas valide ou a expiré	Vérifiez votre clé secrète dans le tableau de bord Cloudflare
missing-input-response	Le paramètre de réponse n'a pas été fourni	Assurez-vous que le jeton est inclus
invalid-input-response	Le jeton n'est pas valide, mal formé ou expiré	L'utilisateur doit réessayer le défi
bad-request	La demande est mal formée	Vérifiez le format et les paramètres de la demande
timeout-or-duplicate	Le jeton a déjà été validé	Chaque jeton ne peut être utilisé qu'une seule fois
internal-error	Une erreur interne s'est produite	Réessayer la demande
Mise en œuvre
Exemple de mise en œuvre
js
class TurnstileValidator {
	constructor(secretKey, timeout = 10000) {
		this.secretKey = secretKey;
		this.timeout = timeout;
	}

	async validate(token, remoteip, options = {}) {
		// Input validation
		if (!token || typeof token !== "string") {
			return { success: false, error: "Invalid token format" };
		}

		if (token.length > 2048) {
			return { success: false, error: "Token too long" };
		}

		// Prepare request
		const controller = new AbortController();
		const timeoutId = setTimeout(() => controller.abort(), this.timeout);

		try {
			const formData = new FormData();
			formData.append("secret", this.secretKey);
			formData.append("response", token);

			if (remoteip) {
				formData.append("remoteip", remoteip);
			}

			if (options.idempotencyKey) {
				formData.append("idempotency_key", options.idempotencyKey);
			}

			const response = await fetch(
				"https://challenges.cloudflare.com/turnstile/v0/siteverify",
				{
					method: "POST",
					body: formData,
					signal: controller.signal,
				},
			);

			const result = await response.json();

			// Additional validation
			if (result.success) {
				if (
					options.expectedAction &&
					result.action !== options.expectedAction
				) {
					return {
						success: false,
						error: "Action mismatch",
						expected: options.expectedAction,
						received: result.action,
					};
				}

				if (
					options.expectedHostname &&
					result.hostname !== options.expectedHostname
				) {
					return {
						success: false,
						error: "Hostname mismatch",
						expected: options.expectedHostname,
						received: result.hostname,
					};
				}
			}

			return result;
		} catch (error) {
			if (error.name === "AbortError") {
				return { success: false, error: "Validation timeout" };
			}

			console.error("Turnstile validation error:", error);
			return { success: false, error: "Internal error" };
		} finally {
			clearTimeout(timeoutId);
		}
	}
}

// Usage
const validator = new TurnstileValidator(process.env.TURNSTILE_SECRET_KEY);

const result = await validator.validate(token, remoteip, {
	expectedAction: "login",
	expectedHostname: "example.com",
});

if (result.success) {
	// Process the request
} else {
	// Handle failure
	console.log("Validation failed:", result.error);
}

Meilleures pratiques
Sécurité
Stockez vos clés secrètes en toute sécurité. Utilisez des variables d’environnement ou sécurisez la gestion des clés.
Valider le jeton à chaque demande. Ne faites jamais confiance uniquement à la validation côté client.
Vérifiez les champs supplémentaires. Valider l'action et le nom d'hôte lorsqu'ils sont spécifiés.
Surveillez les abus et enregistrez les validations échouées et les modèles inhabituels.
Utilisez HTTPS. Valider toujours via des connexions sécurisées.
Appelez uniquement l'API Siteverify dans votre environnement backend. Si vous exposez la clé secrète dans le code client frontal pour appeler Siteverify, les attaquants peuvent contourner le contrôle de sécurité. Assurez-vous que votre code côté client envoie le jeton de validation à votre backend et que votre backend est le seul appelant de l'API Siteverify.
Performance
Définissez des délais d’attente raisonnables. N'attendez pas indéfiniment les réponses de Siteverify.
Implémentez une logique de nouvelle tentative et gérez les problèmes de réseau temporaires.
Résultats de validation du cache pour le même jeton, s'il est nécessaire à votre flux.
Surveillez la latence de votre API. Suivez le temps de réponse de Siteverify.
Gestion des erreurs
Avoir un comportement de secours en cas de défaillance de l'API.
Utilisez une messagerie conviviale. N'exposez pas les détails des erreurs internes aux utilisateurs.
Enregistrez correctement les erreurs pour le débogage sans exposer de secrets.
Limite de débit pour se protéger contre les inondations de validation.
