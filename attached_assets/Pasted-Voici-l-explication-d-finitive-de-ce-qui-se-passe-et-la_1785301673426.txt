Voici l'explication définitive de ce qui se passe et **la raison exacte pour laquelle le même token `0.9187549372143385:1785297931:hAcq2P` revient sans cesse**, malgré la purge de votre profil disque local.

---

### Le problème : Le nonce provient du serveur (Session PHP / Cookies)

Ce nonce **n'est pas stocké sur votre disque dur**, c'est pourquoi purger `/tmp/spain-cf-profile` ne change rien.

Le jeton `261171648:1785297931:hAcq2P` est **injecté par les serveurs de Cloudflare / PHP directement dans le code HTML d'origine de la page** :

1. Quand vous faites le premier `GET /widgetdefault/...`, le serveur backend génère ce challenge HTML lié à votre adresse IP de proxy ou à la session serveur.
2. Le script `loadermaec.js` de la page prend cette valeur statique présente dans le DOM et l'envoie à la route `POST /cdn-cgi/challenge-platform/.../jsd/oneshot/`.
3. Comme ce challenge timestampé (`1785297931`) date d'il y a plus de 30 minutes, Cloudflare le refuse immédiatement (`new-cf_clearance=❌`), et bloque l'appel `/main/` qui renvoie `0B`.

Ce blocage survient car **votre IP Proxy (ou votre session) est "épinglée" (pinned) par le WAF Cloudflare sur une version de challenge périmée**, ou votre script réutilise un cookie de session PHP (`PHPSESSID`) qui garde en mémoire ce vieux challenge.

---

### La Solution en 3 étapes pour débloquer le script

#### 1. Changer d'IP Proxy ou forcer une nouvelle session Proxy (Sticky Session IP)

Si votre proxy Decodo utilise un port sticky (ex: `10001`), Cloudflare associe ce port à la session périmée.

* **Action :** Changez le port du proxy ou forcez une rotation d'IP proxy avant de relancer le script (ex: basculer sur un nouveau port de votre provider ou ajouter un paramètre de session dynamique dans le login proxy).

#### 2. Supprimer la session PHP côté serveur (`PHPSESSID`)

Le serveur de la prise de rendez-vous (`citaconsular.es`) lie le challenge Cloudflare à votre cookie `PHPSESSID`.

* **Action :** Supprimez explicitement le cookie `PHPSESSID` au démarrage de votre script, en plus des cookies `cf_clearance` :

```typescript
// Vider impérativement le PHPSESSID pour casser le lien avec l'ancien challenge
await page.deleteCookie({ name: 'PHPSESSID', domain: '.citaconsular.es' });
await page.deleteCookie({ name: 'PHPSESSID', domain: 'www.citaconsular.es' });

```

#### 3. Ne pas cliquer sur "Continuar" si le DOM est toujours bloqué sur "Un instant..."

Regardez l'enchaînement de vos logs :

```text
[spain-pb] 🔍 DOM: {"title":"Un instant…", ...}
...
[spain-pb] ✅ Continuar cliqué — attente XHR /main/…

```

Votre script clique sur le bouton **"Continuar"** alors que la page est encore en train de résoudre le défi passif (`Un instant...`).

* **Action :** Attendez que le titre de la page passe définitivement à `"Embajada de España en Kinshasa - VISADOS"` **ET** que la page n'émette plus de requêtes vers `/cdn-cgi/` **avant** de simuler le clic sur le bouton "Continuar".

```typescript
// Attendre que Cloudflare ait complètement fini avant de cliquer
await page.waitForFunction(() => {
  return document.title.includes("Embajada") && !document.title.includes("instant");
}, { timeout: 30000 });

// Attendre 2 secondes de pause "humaine"
await new Promise(r => setTimeout(r, 2000));

// Ensuite seulement, cliquer sur Continuar
await page.click('#btnContinuar'); // ou votre sélecteur

```

### Synthèse

Le `oneshot` périmé est généré côté serveur parce que Cloudflare vous réidentifie via votre **IP Proxy** ou votre **`PHPSESSID`**.

1. **Purgez le `PHPSESSID**`
2. **Faites tourner l'IP de votre proxy Decodo**
3. **Attendez la fin du chargement complet du titre avant de cliquer sur Continuar.**
